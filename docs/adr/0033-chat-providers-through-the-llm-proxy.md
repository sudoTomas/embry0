# ADR 0033: Every chat-completions provider is reached through the llm-proxy, which holds its key; a run's calls are held to its provider

Status: accepted (2026-11-26). Amends [ADR 0008](0008-llm-credential-in-sandbox-env.md) (no chat-completions provider's key is in a sandbox's env), [ADR 0018](0018-openai-compatible-providers.md) (the OpenAI-compatible providers are reached through a proxy, not with a key of the sandbox's own), and [ADR 0023](0023-local-llm-proxy.md) and [ADR 0032](0032-custom-provider-through-the-local-llm-proxy.md) (the proxy, renamed the llm-proxy, carries every chat-completions provider's calls, not the custom provider's alone).

ADR 0008 put each provider's key in the sandbox's env, the OpenAI-compatible ones under a reserved `EMBRY0_LLM_` name, where any code a job runs can read it. Their runs were charged what the sandbox reported. Since #688 a run whose calls pass a metering proxy is charged what the proxy counted, which code in the sandbox does not touch; until now that held for xAI's runs and the custom provider's.

So the llm-proxy serves each chat-completions provider at its own path, `/p/<provider>/v1/chat/completions` and `/p/<provider>/v1/models`, and holds its key:

- **The enrollment.** A sandbox whose job resolved OpenAI, OpenRouter, Google, Groq or DeepSeek is enrolled with each one's server: the credential's id, the provider's API root (the catalogue's), the key, and the address the root's host resolves to on the orchestrator, checked as ADR 0032 checks a custom server's and connected to by every call, with the name kept for `Host` and the certificate. The proxy confirms each server, never its key, and the orchestrator refuses a proxy that does not, at create and when a paused job resumes. A provider the enrollment does not name is refused there. The key is registered for exact-value scrubbing where the sandbox manager resolves it, and an answer that names a key the proxy holds (a provider's error message may quote the key it was sent) has it replaced on its way back to the sandbox, however the stream splits it: each key as written (not an escaped or encoded form of it), none shorter than 8 characters. A server is asked for uncompressed answers, and an answer in an encoding the proxy does not decode (anything but gzip or deflate) is refused, never relayed.
- **The sandbox.** It gets no key. The orchestrator points the run's provider record at the provider's path at the proxy (`via_proxy`), and the run authenticates with the sandbox's bearer file, as a custom run does. Such a run is started with `--llm-proxy`, which a runner that predates the route refuses before any call: the run is refused as a stale image (`ERR_SANDBOX_IMAGE_STALE`). A paused sandbox created with a provider's key in its env is not resumed (`ERR_SANDBOX_ROUTE_RETIRED`), its egress closed first, as ADR 0032 does for a custom key. The custom provider keeps the root its sandbox's env names, the proxy's `/v1`, which images built before this read.
- **A run is held to its provider.** The orchestrator's declaration of a run at the metering proxies names its record's provider. While the run is current, the llm-proxy refuses the sandbox's calls to every other provider's path (403, `provider_not_declared`), so the run's tally holds its own provider's calls, names that provider, and is priced at the run's rates. A tally at the llm-proxy that names another provider, or none (a proxy image that predates this), is not taken as whole: the run is charged the larger of the proxy's count and the sandbox's figure. So is a run that could not be declared on a metering proxy whose calls still went through it (the custom provider's `/v1`, the xai-proxy): they counted under the sandbox's calls under no run, and the proxy's count of the run is what those grew by during it. A provider's path refuses such a run's calls (below).
- **A run is held to its budget** (amended 2026-11-27). The declaration carries what the run may still spend, the least of what its job has left under its cap and what the deployment has left today and this month under its caps, where each is set, and the run's rates. Both metering proxies refuse a call whose ceiling, priced at those rates, would take what the run has been charged, its calls in flight at their ceilings included, past that (402, `budget_exceeded`), and send nothing of it. This holds in every overrun mode: it refuses a call and stops no run, so what a crossing of the job's cap does to the job is still its overrun mode's. A free run, a run with no cap set and a declaration without a budget (an older orchestrator) are not checked. A run that fails after a call of it was refused carries `ERR_BUDGET_CALL_REFUSED`.
- **No call outside a run.** A provider's path takes calls during a run alone: before a sandbox's first run is declared, and after its run ends, `/p/<provider>/v1` is refused (403, `run_not_declared`) and reaches no provider, so every call there is charged to a run. The custom provider's `/v1`, which images built before this call, still forwards outside a run, counted as the sandbox's calls under no run.

Not changed: `METER_REQUIRE_RUN` stays off, so the custom provider's `/v1` and the xai-proxy still forward a sandbox's calls under no run, counted as unattributed. The orchestrator's own calls (background calls, probes) reach the providers directly with their keys. Anthropic's and xAI's runs are as ADR 0008 and the xai-proxy have them.

Consequences: no chat-completions provider's key enters a sandbox, and such a run is charged what the proxy counted. A job on one of these providers does not start without the llm-proxy, or when a provider's root resolves to nothing or to an address embry0 does not reach. An address is pinned for an enrollment: a provider that moves its address is reached at the new one from the next enrollment. The proxy image and every sandbox image must be rebuilt before the release runs: an older runner refuses such a run, and an older proxy does not hold a run to its provider.

Evidence: `embry0/execution/proxy/llm_proxy.py` and `embry0/execution/proxy/metering.py`; `embry0/orchestration/run_budget.py`; `_provider_servers` and the resume in `embry0/execution/sandbox_manager.py`; `route_through_llm_proxy` in `embry0/execution/agent_runner.py`; `embry0/agents/run_charge.py`.
