# ADR 0020: The files that steer a coding agent are audited on a schedule, anchored on the recorded jobs, and only when they or the code moved

Status: accepted (2026-10-23)

A coding agent takes `CLAUDE.md`, `AGENTS.md`, a skill or a rules file as instructions, so a line in one that went stale reaches it as a fact, and nothing in a repository says when one went stale. An organization whose `context_audit_days` setting is on (1 to 365, off by default) has them audited without anyone asking: an orchestrator loop wakes every 15 minutes and, for each active registered repository under each such active GitHub owner, reads the default branch's head and recursive tree with the organization's credential, selects the instruction files by the one glob list the auditor's prompt also reads (`embry0/services/instruction_files.py`), and fingerprints them (sha256 over the sorted `path<TAB>blob sha` lines). A repository with none is left alone. One is due when it has no `context-audit` job yet, when the fingerprint differs from the one its newest such job recorded, or when that job is `context_audit_days` old and the branch head moved since; never while one is pending, running, awaiting input or paused. The newest job is the anchor whatever became of it, as rediscovery's runs are (ADR 0016): a completed job from when it finished, a failed one from when it started, so a failure waits a full interval and nothing retries on every tick; a start refused before any job existed counts the same, remembered until the process restarts. A due repository gets a job through the path `POST /jobs` takes (the job row, a `job_created` audit row, the executor), on the `context-audit` template, with a hard per-job budget like the watcher's (`CONTEXT_AUDIT_JOB_BUDGET_USD`, 2 USD) and at most `CONTEXT_AUDIT_MAX_JOBS_PER_TICK` (3) per tick, attributed to `embry0:context-audit`, which the per-author rate limit still brakes. The job records the fingerprint and the head it was started for. The start is refused while no template carries that name, because plan_route sends a job whose named template is missing to the default for its kind, a code job; and the newest-job lookup also matches the schedule's actor, because plan_route rewrites a job's template column with the template it resolved.

Evidence: `embry0/services/context_audit.py` (`due_reason`, `fingerprint`, `ContextAuditLoop`, `start_context_audit_job`); `JobsRepository.newest_per_repo`, one query per owner over `idx_jobs_repo` and no migration; `plan_route_node` in `embry0/workflows/issue_to_pr/plan_route.py`, whose fallthrough for a missing named template is why the start checks the template first; `GET /api/v1/orgs/{owner}/context-audit`, which reads through the same loop.
