# ADR 0016: Rediscovery runs on a schedule, and a vanished repository is only proposed for deactivation

Status: accepted (2026-10-18)

An organization whose `rediscover_hours` setting is on (1 to 168, off by default) is rediscovered without anyone asking: an orchestrator loop wakes every few minutes and starts a run, through the function `POST /orgs/{owner}/discover` uses, for each active owner whose newest run is that many hours old. The recorded run is the anchor, so a restart neither postpones nor repeats one, and a failed run waits a full interval. So does a start refused before any run exists (the owner's credential cannot be resolved): the loop remembers the refusal until the process restarts. A new repository reaches the needs list as `not_registered`. One an earlier run listed and the newest did not, still an active registration, becomes the `repo_vanished` need with the `deactivate` action, never deactivated on its own: a narrowed credential looks the same as a deletion. Before it counts, the run confirms each candidate one by one with a direct read of the repository: the listing pages over newest push first, so a push during it can move a repository onto a page already read, and the repositories embry0 pushes to are the likeliest to move. A 404, a 301 or the record under another full name confirms the departure; the same repository means the listing missed it; any other answer is unknown, and unknown is not gone, so a flaky forge proposes nothing. A listing the page cap (20 pages of 100) stopped early confirms none, since it leaves out repositories that are still there, and neither does a run with more than 50 candidates. `deactivate` is the one action that reaches an archived row, since a repository archived when it was last listed and deleted since is such a registration.

Evidence: `embry0/services/org_rediscovery.py`; the `org_discovery:<owner>` lock in `OrgReposRepository.start_run`; the strict listing in `org_discovery.list_repositories`, since a refused page used to end the listing early; `org_discovery.confirm_gone` and the `vanished_run` stamp `note_vanished` writes, since a push during the listing, or the page cap, used to read a repository still there as gone; `ForgeClient.paginate_listing`, which says whether a listing is whole.
